# 目标问题解决

从「目标 → 七步问题解决」打开当前目标的记录。使用当前生效的目标版本界定问题。各子域分别保存工作对象、版本和证据，可以同时推进多条分支。

| 子域 | 主要对象 | 典型循环 |
| --- | --- | --- |
| 问题界定 | 问题、问题版本、基线、成功标准 | 登记、确认、依据实际反馈修订 |
| 问题拆解 | 分支、假设版本、反证重评 | 拆解、登记假设、针对受影响分支重评 |
| 优先取舍 | 优先评估、影响、可干预性、成本 | 排序或暂缓，满足条件时重新评估 |
| 验证规划 | 验证方案版本、验证批次、关联任务 | 固定判据、独立确认、发起批次、补证 |
| 证据分析 | 原始证据引用、观察、独立结论 | 回收证据、复核、确认支持、反证或证据不足 |
| 结论综合 | 综合论证版本、主张、证据、取舍 | 拟定、复核发布、在依赖变化后重开 |
| 目标决策 | 决策、修订提案、目标版本 | 维持、调整、暂停或终止，登记复查条件 |

## 发起和回收假设验证

在「验证规划」选择已确认的假设和验证方案版本。选择一个已关联的任务，或填写新任务标题。平台在同一事务内创建并关联新待办和验证批次。任务正文带入样本、对照、判定阈值和停止条件。可按既有任务流程分配待办。

从「证据分析」回收实际观察和可复核证据。由不同的执行者独立复核。证据不足时可引用原批次发起补证。反证会把对应分支标为待重评。迟到的结论保留在所验证的版本中。

## 修订目标

以当前目标版本为基线，引用已独立复核的综合论证提交提案。目标创建者或工作区管理员可以采纳。采纳保存新版本和历史回执，沿用原目标、计划节点和任务 ID，并要求按新目标复审计划。纯优先级调整在优先取舍与计划中处理。

## 代码入口与复跑

- Go 领域规则和先红后绿用例位于 `server/pkg/goalproblem`。按子域组织，跨域后果集中在 `process.go`。HTTP 层校验角色、工作区和任务归属，在目标的事务内提交领域决策、目标版本和计划变化。
- 智能体可用 `multica goal solve <目标 ID>` 读取。写入同一入口时传 `--expected-revision` 和 `--file`，文件内写动作及其业务输入。发起验证批次时可加 `--new-task-title` 创建关联任务。
- 在 `server/` 运行 `go test -count=1 ./pkg/goalproblem`。用已迁移的隔离 PostgreSQL 运行 `go test -count=1 ./internal/handler -run TestGoalProblemSolving`，复验同一目标升版、任务关联以及旧计划授权失效。
