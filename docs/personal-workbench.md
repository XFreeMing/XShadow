# 个人工作台运行方式

这个项目是用户自己的可定制工作台，承载跨项目的智能体军团。用户会在不同电脑和操作系统之间切换，平台也会随使用持续增加个人功能和优化。军团可以承接平台自身的改进任务，同时继续服务其他项目。

## 一个共享工作区，多台电脑接入

采用一个共享服务和工作区保存持续工作的状态。各电脑连接同一服务，使用同一账号和工作区；不为每台电脑复制一套日常业务数据。

| 内容 | 存放与同步方式 |
| --- | --- |
| 平台源码、军团模板、可复用技能 | Git；通过明确版本共享和更新 |
| 项目、任务、评论、会话记录、智能体配置、运行记录 | 共享服务与工作区 |
| 本机 CLI 安装和登录、执行目录、未提交修改、CLI 会话文件 | 各执行电脑本地管理 |
| 服务数据库、上传文件及必要服务配置 | 服务端持久化与备份；不由 Git 或军团初始化替代 |

桌面客户端、CLI 和 daemon 的服务配置有不同入口，不会因为 clone 了同一个仓库就自动连接同一个服务。具体接入参见[桌面自托管连接](../apps/docs/content/docs/desktop-app.zh.mdx#连接自托管实例)和[CLI](../apps/docs/content/docs/cli.zh.mdx)。服务地址需要让使用端和执行端都可达。

共享服务应运行稳定版本，并能在用户切换电脑后继续访问。服务部署在哪台常驻设备、使用什么地址及备份位置尚未指定，本文不代表已完成共享部署。

## 使用电脑与执行电脑分开

用户从电脑 A 换到电脑 B 查看任务或继续沟通，不应自动改变任务执行位置。A 上的 daemon 可以继续执行；B 也可以作为使用端，不必为浏览记录安装全部模型 CLI。

当 B 需要执行任务时，再安装所需 CLI、完成本机认证并连接工作区。每台电脑可以只提供自己具备的能力，例如不同操作系统的构建或验收环境。

当前智能体绑定一个 `runtime_id`。已有运行时发现、在线状态和重新绑定能力，但不能据此宣称已具备多机自动调度、故障转移或运行中任务无缝迁移。人工切换执行位置时，先确认正在运行的任务、代码与未提交修改、产物及本地会话的交接条件，再决定在哪台电脑继续；服务端保留的记录不等于整个本地执行状态已经搬迁。

`make agent init` 的边界如下：

- 无 profile：准备当前检出的独立本地开发环境并初始化军团。
- 指定 profile：在已登录的目标工作区同步模板，也会重设模板角色的运行时绑定。
- `--check`：检查目标身份、运行时与模型，不修改军团配置。

因此，日常换电脑使用客户端不运行 `init`。新增或更新军团配置时，才按[初始化说明](../agent-team/README.md)操作。

## 军团参与平台自身改进

平台改进是用户交办的一类项目任务，不是军团唯一或默认的工作目标。明确交办平台任务时，任务说明提供仓库、目标版本、期望行为、影响平台和验收条件，不把这些信息固化到领域专家的人设。

协作责任沿用现有分工：

1. 项目经理使用 Grok 维护需求入口、计划、负责人、依赖和交接。
2. 一般研究、设计与沟通由 Grok 完成；复杂技术拆解、架构及争议交给 Codex。幕僚长处理跨项目优先级与资源冲突。
3. 对应领域的 Claude Code 工程师实施代码、测试和工具修改。
4. Grok 或 Codex 根据难度独立审核，质量交付经理核对验收证据。
5. 发布工程按已授权范围构建和交付，确认后将可复用经验更新到领域技能；项目特例留在项目记录。

开发使用独立 worktree、分支和受管开发环境，保留用户现有改动。一项需要集成验证的功能保持一个明确负责人，不按前后端层次机械拆分。军团依赖的共享服务运行稳定版本，避免把正在实验的工作副本直接替换成协调所有任务的服务。

平台改进的跨平台声明以实际证据为准。Linux 上验证通过，不代表 Windows/macOS 桌面生命周期、文件路径、进程管理、CLI 发现和打包均已通过。当前初始化入口依赖 Bash/Make；Windows 的已文档化使用路径是 WSL，原生 Windows 一键入口不能标记为已支持。

## 后续功能优先级

以下是依据个人多机使用方式确定的建设方向，不是已完成能力：

1. 简化连接共享服务的客户端配置，明确区分连接、初始化与模板更新。
2. 让模板更新与执行设备切换成为独立操作，避免更新角色时顺带改变执行位置。
3. 建立设备能力、在线状态、执行位置和任务交接的清晰入口。
4. 验证不同操作系统的客户端及执行端，补齐适合各平台的初始化方式。
5. 将平台自身的研发、验收、版本交付和技能积累串成可追溯的项目流程。

具体功能仍由用户指定范围后推进，不自行创建长期任务、轮询日程或无限扩编。
