# 新会话如何接续军团管理

此文件是新增或调整智能体时的入口。具体名册与配置读取 `team.json`；实时状态从目标工作区查询，不把聊天历史或旧截图当作当前状态。

## 已确定的使用方式

- 这是用户个人、跨项目的智能体军团，运行平台不是默认服务项目。
- 日常多机使用一个共享服务和工作区。换使用电脑不自动迁移执行位置或重绑智能体。
- 实现使用 Claude Code 的 `deepseek-v4.1-flash / high`；一般与中等难度分析、研究、设计、审核、沟通使用 Grok；复杂工作使用 Codex。
- 项目经理负责日常计划与推进，幕僚长负责跨项目决策，领域经理和专家负责各自交付。技术专家跨项目复用，项目路径与规则随任务提供。
- 领域能力通过经审核的技能和验证案例积累，不声称底层模型会自动训练。
- 不因为读取上下文而启动任务、自动化日程、服务或扩编。

完整运行方式见[个人工作台运行方式](../docs/personal-workbench.md)。模型型号、角色数量、成员和技能以实际模板与实时查询为准，不在本文复制一份容易过期的名册。

## 开始调整前

```bash
make agent context
```

命令输出读取时间、目标服务和工作区、长期规则、角色与模型、技能绑定、小队关系、运行时在线状态，以及模板与实时配置的差异。只发出读取请求，不探测模型目录或启动模型。

目标选择顺序为 `--profile`、本机 `agent-team/local.json`、`MULTICA_DEV_PROFILE`、当前检出的托管环境 profile。共享工作区应在每台电脑配置自己的登录 profile，再把默认读取目标写到 Git 忽略的文件：

```json
{"profile":"my-team"}
```

这里的 `my-team` 必须是已经登录并选择正确工作区的 CLI profile。该文件只影响上下文读取，不改变 `make agent init` 的目标选择。凭据仍由本机 CLI 管理，不复制进仓库。

也可以显式选择目标或输出 JSON：

```bash
make agent context ARGS="--profile my-team"
make agent context ARGS="--profile my-team --json"
```

服务不可达或没有可用 profile 时，命令仍输出模板，并标记实时状态未核验。需要完全离线阅读时：

```bash
make agent context ARGS="--offline"
```

离线结果只能支持方案准备，不能证明服务端缺少角色，也不能作为覆盖服务端配置的依据。JSON 中 `live.status` 的 `verified`、`unavailable`、`offline` 必须分别处理；退出码为零不等于已核验实时状态。

## 调整与交接

1. 核对目标工作区和差异。额外角色可能是用户在界面中新增的；缺失角色也可能是改名。先理解这些变化，避免重复创建。
2. 查看要改的角色、技能或小队完整配置。上下文摘要不会打印完整实时提示词、自定义环境变量、MCP 配置或登录 token。
3. 在用户授权范围内实施变更。将可复用的角色、人设、模型、技能与成员关系同步到仓库模板；设备绑定与凭据保留在目标环境。一次局部调整不应顺带全量重绑运行时。
4. 读回受影响配置，再运行 `make agent context`。说明哪些差异已解决、哪些是有意保留，以及是否存在只改模板但尚未应用的部分。

新会话无需继承旧会话的隐式记忆。它需要打开此仓库、读取 `AGENTS.md`，并能访问选定的 profile。任意未关联仓库的聊天不会自动获得这些内容；可给该会话仓库路径和本文件作为入口。

平台内部的“智能体构建师”通过已分配的 `rd-build-agent` 技能，先查询工作区中的角色、小队、技能和运行时再设计调整；它不依赖本机仓库路径。仓库会话与平台会话都应先读实时状态，再落地变更。
