# 从领域规则到用户入口

在故事已有的四步中使用本技能。挑本次可能误判的规则，将结果写回该步原有的标准、用例或回执。

故事负责人先亲自尝试当前入口，用代表性样本分析谁在什么情境下想完成什么、哪里会卡住。由这些事实提出最小可用增量，写清用户怎样知道完成、各环节的取舍和怎样验证，再设计规则、接口、交互与测试。涉及界面时，让评审者在原事项的可操作原型里自行改变输入、身份或状态，再判断能否完成关键任务、看懂反馈并从失败恢复。原型和真实入口使用同一批代表性场景，实际反馈带回下一小步。

按具体问题查看[经验与检验方式](references/experience.md)。设计实体、跨服务事务、替身或遗留代码测试时，查[原书核对与验证示例](references/design-and-test.md)。

涉及性能优化或协作提效时，查[定位瓶颈与对照复验](references/experience.md#定位瓶颈与对照复验)，用实际入口和运行记录选定一个改动点。

研发故事按一个史诗一个目录归档。每个短 US 编号对应一份故事 Markdown 和同级的专属 TDD 目录，其中保存可运行的用例和测试数据准备代码。原事项链接故事，故事链接项目统一语言表、领域接口与数据结构、测试目录和复跑命令。术语表按限界上下文对应业务词、定义与代码标识符，需求、界面、实现和测试沿用同一含义。见[任务承接的可运行样例](examples/agile/epics/task-ownership/US-01.md)。

1. **定义增量。** 从业务方的一句话提取角色、触发条件和可观察结果。遇到同名异义，用具体例子说清对象身份、适用上下文和谁确认。跨角色履约时对读请求与确认。遇到算法或模型选择，先试已有方案；涉及聚合、事务、投影或跨服务发布时，写明必须保持的不变量、失败场景和选择依据。按遇到的问题查阅相应经验。[建模经验及适用边界](https://app.notion.com/p/41b0cfe0ebfa8112a431d936b97d4bce)
2. **设计用例。** 从获准的输入原件独立写出预期，再看实现。提出一种会通过普通样例的错误实现，用最靠近业务分界的一对样例区分它。记录每个断言会放过什么。当既有行为缺少保护时，先从入口观察并记录需要保留的部分，单列本次要改变的预期。[TDD 经验条目](https://app.notion.com/p/41c0cfe0ebfa816bb2f3f49c82885fb7) · [表征测试](https://app.notion.com/p/41d0cfe0ebfa81ef84d3ebb2548ebfdd)
3. **实现候选。** 新行为先运行目标断言，核对失败原因，再做最小实现，转绿后跑相关回归；有重构再复跑。保留基线、候选 SHA、输入、命令和实际输出。补测既有行为允许直接绿，说明保护范围。事后在旧 SHA 上回放，可以证明断言有区分力；声称测试驱动了实现还需要当时的先后记录。
4. **独立验收。** 从原标准重建预期，在候选的实际入口复演正例和反例。对替身的交互断言只能证明调用者发出了约定调用。跨组件结论还要从实际配置核对真实依赖收到什么、产生什么业务效果。把差异定位到词义、断言或实现，交回相应步骤。交接只补充新结论、证据定位和待判事项。[工程经验索引](https://app.notion.com/p/41d0cfe0ebfa8158b8a6c45c5f05e93d)

实现前在原故事冻结这次受影响的实体和接口。写清实体身份、状态、不变量，以及每个输入和返回字段的名称、类型、来源、必填或可空、约束和错误。按适用范围列鉴权、状态变化、副作用和兼容行为。每个可变条件至少有一对能判对错的样本。写不出判定用例时，回需求与设计阶段讨论需求理解、业务冲突和边界，把争议转成具体输入和预期后再做 TDD。已有确定预期但执行环境不具备时，按环境问题记录。

在 `US-01-tdd/` 固定样本来源及修订、生成命令、前置状态、实际输入与逐字段预期。覆盖代表性用户数据和最靠近规则分界的反例，以及适用的失败、权限、旧数据、重试或重放。预期来自获批原件和业务规则，在实现前核对。用固定种子、时钟或身份让样本可重复，记录脱敏或合成的依据。让同一判定在旧基线因目标业务规则失败，再在候选转绿。

## 检索故事的辨别例

先问“一份佐证”如何计数。同一原文位置出现在整本、分章和已登记的同源摘要中，只计一份；同一文字出现在两个原文位置，两处都要能打开。一个按返回行计数的实现会在前例多算，一个仅按文字去重的实现会在后例少算。拿一个能人工数清的小原件，先标出预期的各处，再从实际 CLI 和 Web 逐一打开返回的位置，核对两边集合相同。若页面同时给出章节锚点和字符偏移，选一个不在首章的例子，按页面写给用户的起点、单位和正文还原所指文字。同一标题进入多个投影时也按原件出现位置计数。从存储层复制一行，只检验了重复返回，仍需用真实的不同视图验证来源关系。

复盘时区分原文主张、模板要求、候选自测、独立复验与用户可用产物。沿用已有运行回执比较等待、返工和模型请求，注明样本与比较范围。只有新故事产生的证据才能支持跨故事收益。
