【待规划入口】
在原有成员答复卡检查之外，复用本轮已取得的开放事项列表检查待规划，覆盖当前工作区全部项目，无需再建立日程。规划执行方是项目经理的运行型自动任务 {{planner_id}}（项目经理处理待规划任务）。当出现尚无 backlog_plan 记录的待规划事项、正文/目标/独立审核或用户决定实质改变、前置事项新近完成、授权或容量条件已满足而尚未接手时，检查此自动任务最近运行；若已排队或运行，交由该轮处理。否则用 multica autopilot trigger {{planner_id}} --output json 派给项目经理并验证平台返回真实运行。失败如实报告，后续轮次补查。在发起前比较 backlog_plan 存下的依据和依赖状态，规划者补写自身评论与 metadata 不能成为新一轮触发原因。无变化时安静结束。不要代项目经理写规划结果或将 backlog 批量转为实施，也不要把内部验证卡作为开工授权。

已有规划记录也要核对执行接续：当下一步的运行已因服务不可用而终止、其回调已消费、没有后续活跃运行或有效等待，且同一工作仍有授权和可用的团队替代角色时，这就是新的规划缺口。比较最近原事项运行/评论/规则与 backlog_plan，特别是只留下“等额度恢复”的事项。对同一未处理的失败派给项目经理走替代接单；已有替代运行或已记录必须等待的真实外部条件则不重复派。此检查使用本轮现有补查。
